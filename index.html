01 · Background

Who We Are & What We Do 背景与目标

Mandala Media is ByteDance's designated overseas influencer marketing agency, headquartered in Hong Kong with teams across Shenzhen and Shanghai. We run global KOL campaigns for clients including BytePlus, Seedance, and CapCut — spanning platforms like TikTok, LinkedIn, YouTube, X, and Xiaohongshu.

The BD team executes a high volume of workflows daily: creator sourcing, campaign management, quote collection, contract review, and payments. Portions of this pipeline are already semi-automated through Claude + Gmail MCP + Google Drive — but three critical automation gaps remain unresolved.

This document serves two purposes:

1. Document the full landscape of BD workflows — which are automated, which are semi-automated, and which remain manual.

2. Define the three highest-priority automation gaps that require AI Agent integration or system bridging — as input for CTO planning.

Not covered here: Marketing strategy, client-facing deliverables, or product decisions.

04 · Gap Analysis

3 Automation Gaps to Resolve 待解决的自动化缺口

The following three gaps represent the highest-impact bottlenecks. Each requires either an API bridge or a new Agent capability to resolve.

GAP 01

Quote Consolidation → Feishu Bridge

报价整理与飞书的 Bridge
P0 — Immediate
Problem
Quote tables are currently output as HTML files or Claude conversation tables. There is no automatic sync to Feishu Bitable or Feishu Docs — team members must manually copy data, creating information lag and omission risk.
Current state
Gmail scan → Claude structure → manual paste to Feishu. Each cycle takes 15–30 min of human effort.
Target state
After Gmail scan completes → auto-write to Feishu Bitable (per Creator / platform / quote / status columns). Team sees real-time updates.
Data fields required
Creator name · LinkedIn / YouTube / X links · Platform type · Follower count · Collaboration format (original post / reshare / video) · Quote amount (per platform) · Currency · Status (pending / quoted / agreed / declined) · Notes
Trigger logic
Manual trigger ("scan quotes, write to Feishu") or scheduled (daily 09:00 auto-scan prior 24h inbox). Dedup on write using Email as primary key.
Tech path
Feishu Open Platform API (Bitable / Docs)
+ Gmail MCP
+ Claude parsing layer
— or via n8n / Zapier middleware bridge
Team impact
Affects all BD team members. Directly impacts quote visibility, follow-up speed, and reporting accuracy.
GAP 02

KOL Payment Registration → Google Sheets Bridge

KOL 付款登记凭证与 Google Sheet 的 Bridge
P0 — Immediate
Problem
Contract registration and voucher upload are semi-automated, but writing to Google Sheets occasionally produces field mapping errors and column drift. Batch processing of multiple contracts is not supported. Wise voucher naming conventions are complex — manual naming remains the main bottleneck.
Current state
Contract PDF → Claude extracts → semi-manual write to Sheet (columns R–AB). Voucher PDF → Claude suggests naming → human confirms → upload.
Target state
Upload contract/voucher → fully auto: extract fields → write to exact columns → auto-name file → upload to Drive → update Sheet status column.
Core risk points
  • Column mapping (R–AB) breaks when Sheet structure changes
  • Batch processing order confusion across multiple contracts
  • Wise naming rules must be bound to Sheet primary key (KOL ID / contract number)
Tech path
Google Sheets API (Sheets MCP connected)
+ Google Drive API
+ Claude extraction layer
Key improvement: column mapping config file (JSON) — structure changes only require config update, not code changes
Team impact
BD + Finance. Directly affects payment compliance and financial data accuracy.
GAP 03

Niche Channel Sourcing — Agencies & Non-Mainstream Platforms

小众渠道 Sourcing（代理机构 + 非主流平台）
P1 — Next Sprint
Problem
Some client requirements involve finding overseas talent agencies (not individual KOLs) or creators on niche platforms (Reddit, LinkedIn). There is no systematic sourcing methodology — highly dependent on manual search and human judgment.
Three sub-scenarios
  • Overseas Talent Agency sourcing: Find agencies representing AI / tech / film KOLs, build agency database
  • LinkedIn creator outreach: Profile → content direction assessment → audience fit scoring → personalized message drafting at scale
  • Reddit native content: Target subreddit → compliance check → community-style promotional content (REDHackathon SOP exists)
Current state
Fully manual: Google search → human filter → send email one by one. No batch LinkedIn sourcing path. Reddit content written individually by hand.
Target state
Agency: specify category + region → Claude web search + structured agency list (size / focus / contact) → auto email drafts. LinkedIn: input URL list → batch profile analysis → match scoring → batch personalized messages. Reddit: specify subreddit + brief → auto-generate community-tone content.
Tech path
Agency: Claude + web_search + structured output template
LinkedIn: Claude in Chrome (profile traversal) + scoring model
Reddit: Claude + community style SOP (REDHackathon reusable)

06 · Architecture

Proposed Agent Layer Structure 建议的 Agent 架构

Built on existing connected tools: Gmail MCP, Google Drive MCP, Google Sheets MCP, Claude in Chrome.

L1
Data Harvesting
数据采集层 · Partially done
  • TikTok One XHR intercept → Creator harvest
  • Gmail MCP → Inbox scan & parse
  • Claude in Chrome → Web scraping (LinkedIn / media)
  • Web Search → Agency / review media research
L2
Parse & Structure
解析结构化层 · Claude core
  • PDF contract field extraction
  • Email intent classification
  • Profile audience fit scoring
  • Quote normalization across currencies
L3
Write & Sync ← GAPS HERE
写入同步层 · Where gaps live
  • Feishu Bitable API → Quote auto-write (Gap 1)
  • Google Sheets API → Exact column write (Gap 2)
  • Google Drive API → Voucher upload (Gap 2 partial)
L4
Output & Interact
输出交互层 · Done
  • HTML reports → screenshot for reporting
  • Email drafts → Gmail Drafts → human send
  • Brief → KOL notice copy generation
  • Contract diff → highlighted PDF / HTML
Core takeaway for CTO: Claude already handles L1 (harvest) and L2 (parse) well. The P0 gaps are entirely in L3 — the write/sync layer. Parsed data currently has nowhere persistent to land. The fix is building stable API bridges from Claude's output to Feishu Bitable (Gap 1) and Google Sheets (Gap 2). Once L3 is solved, all upstream work automatically becomes fully automated.

当前核心问题：Claude 能解析，但解析结果没有稳定的落地目的地，仍需人工转录。解决 L3 = 上游所有半自动流程自动升级为全自动。
