Agent Layer Architecture Agent 分层架构

L1
Harvest · 采集
Largely done · 基本已有
  • TikTok One XHR intercept
  • Gmail MCP inbox scan
  • Claude in Chrome scraping
  • Web search for agencies
L2
Parse · 解析
Claude core · Claude 核心能力
  • PDF contract field extract
  • Email intent classify
  • Profile fit scoring
  • Quote normalization
L3 ← GAPS
Sync · 同步写入
Where the gaps live · 缺口所在
  • Feishu Bitable API (Gap 1)
  • Google Sheets exact write (Gap 2)
  • Drive upload — partial ✓
L4
Output · 输出
Done · 已有
  • HTML reports
  • Gmail Drafts (human send)
  • Notice copy generation
  • Contract diff highlights
Core message for CTO: L1 (harvest) and L2 (parse) are working well. The P0 bottleneck is entirely in L3 — the sync layer. Parsed data has nowhere persistent to land, so manual transfer remains. Fix L3 → all upstream semi-auto work becomes fully automated.

对 CTO 的核心结论：Claude 能采集能解析，卡在 L3——解析结果没有稳定落地目的地，还在靠人工转录。解决 L3 的两个 API bridge，上游所有半自动流程自动升级为全自动。

Discussion Points 讨论议题

01

Feishu API Access · 飞书 API 权限

Does our Feishu tenant have an open-platform app configured? Can we get Bitable read/write permissions? · 飞书租户是否已有开放平台应用，可申请 Bitable 读写权限？

02

GWorkspace Service Account · GWS 服务账号

GDrive / GSheets MCP is connected. Do we need a service account for stable background / scheduled tasks beyond the MCP session? · 是否需要 service account 支持后台定时任务？

03

Data Security · 数据安全边界

KOL quotes and contract figures are sensitive. What permission controls apply when writing to Feishu / GSheet? · 报价和合同金额敏感，写入协作工具的权限控制策略？

04

Trigger Model · 触发机制

Manual-first to validate accuracy, then scheduled cron once stable? · 建议先手动触发验证准确性，稳定后再转定时任务？

05

Agency Data Persistence · 代理机构数据沉淀

Should agency sourcing results persist in a unified CRM (Feishu Bitable or Notion) for future reuse? · 搜索到的 agency 信息是否需要建立统一 CRM 记录以便复用？

06

Platform Compliance · 平台合规

Compliance boundaries for automated content on Reddit (anti-bot rules) and LinkedIn (bulk limits)? · Reddit 反机器人规则和领英批量操作限制的合规边界确认？
